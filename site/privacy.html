Source preview notice · 12 November 2026

Your records stay close.

This notice describes this source preview. The deploying operator must add its identity, contact details and retention policy before public launch.

On your Android device

Transactions, budgets, goals, account labels, source message identifiers and sync checkpoints are stored in a SQLCipher-encrypted Room database. Its random key is wrapped using Android Keystore. Full email bodies are processed in memory and not retained in the financial database. Android app backups are disabled.

Gmail access

The app requests the Gmail read-only scope, not permission to send or delete mail. Initial import uses your search and selected history window. Incremental checks inspect newly added messages. Unsupported formats produce no transactions. You can stop collection in Settings and revoke the grant through Google's connections settings.

Authentication and consent

When configured, the API on Fly.io and Supabase PostgreSQL store your phone authentication, sessions and consent events. The SMS provider receives your phone number and the verification code for delivery. Financial records are not uploaded to this API.

Optional analytics

Firebase Analytics collection is disabled by default. If configured and you opt in, Firebase may receive app usage and device analytics. Transaction amounts, merchants, source emails and account references are never intentionally included in analytics events. You can turn collection off in Settings.

Exports, deletion and retention

Exports happen only when you choose a destination. Export files are unencrypted financial information. Deleting local data does not remove exports, Gmail messages or cloud authentication records. Signing out keeps the separate encrypted local database for that app user. Settings also offers cloud-profile deletion, which removes authentication and consent records and deletes local financial data for that app user. Revoke the Gmail grant separately at Google.

No payments or cloud assistant

The app cannot initiate payments and never asks for a UPI PIN or bank password. The read-only assistant uses local intent handling and database calculations. It does not send financial information to a cloud model.
